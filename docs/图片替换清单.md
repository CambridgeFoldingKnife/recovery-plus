## 一、需要替换的 5 张图

| # | 文件名 | 用在哪个区块 | 前端容器约束 | 生成比例 | 建议生成尺寸 |
|---|--------|-------------|-------------|---------|-------------|

### 核心规则（零留白）

- **产品卡（2.JPG / 8.png）**：容器固定 4:3，`object-contain` 把图完整放进框内。图窄了 → 左右露深灰底色；图宽了 → 上下露底色。**必须生成 4:3** 才铺满、零留白。
- **产品洞察（9.JPG）**、**场景（7.png）**：没有固定裁切盒，按自然比例缩放、高度自适应。按 img 标签写死的 16:9 / 4:3 生成，区块高度最稳定。
- **Hero 背景（hero.png）**：`bg-cover` 会裁剪填满，任何比例都不会留白，只求高清。

## 二、画面内容建议

- **2.JPG / 8.png（产品图）**：产品全身入镜、主体居中、留出均匀呼吸空间（避免主体顶到画框边缘）。两张分别对应「高压便携款（外置泵，轻量）」和「全能一体款（内置泵，带热敷振动）」，画面要有区分度。
- **9.JPG（产品洞察）**：运动员/跑者训练后使用恢复靴的场景氛围图，情绪化、有故事感（呼应「恢复是训练计划的下一项」文案）。
- **7.png（恢复场景）**：运动后放松恢复的使用场景图，与 9.JPG 拉开构图差异（如居家/客场/健身房的视角区别）。
- **hero.png（首屏背景）**：大气、留黑位（首屏上有文字，背景要偏暗、中间偏纯色，方便文字识别）。

## 五、替换流程

1. 按上表比例生成 5 张图。
2. 保存为**同名文件**，覆盖 `public/assets/` 下原文件（扩展名建议保持 `.JPG` / `.png`）。
3. 如生成的是别的格式（WebP/AVIF 等），可交给 Claude 统一转换并替换。
4. `npm run dev` 本地验证：4:3 产品卡铺满无留白、高清无模糊，再提交。

> 提示：生成分辨率建议不低于表中「建议尺寸」，否则在高清屏上会被放大发虚。
